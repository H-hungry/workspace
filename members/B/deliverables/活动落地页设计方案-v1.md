# 苹果早鸟票活动落地页设计方案 v1

## 一、方案概述

### 1.1 问题定位

首版落地页会员开通转化低于预期。结合活动机制分析，根因在于页面信息主线与用户的决策旅程错位：用户进入页面时首先关心的是"这个活动跟我有什么关系、我要做什么"，而首版页面未将「开 PLUS = 获得抢购资格」这一因果链前置，导致动机未被激活就要求用户完成开卡动作。

### 1.2 设计主线：一条机制链 = 一条浏览动线

页面不发明新逻辑，直接把活动机制链翻译为从上到下的浏览动线，让用户每往下滑一步，就离抢购资格近一步：

```
开通 PLUS（获得参与资格）→ 旧机估值（获得抽签码）→ 每日抽签（等结果）→ 中签预约 → 抢购下单
```

四个核心模块按此链路顺序排布，各自回答用户在该阶段的一个核心疑问：

| 模块 | 用户疑问 | 模块回答 |
|---|---|---|
| 会员开通引导 | 我凭什么能买？ | 开 PLUS 即获抢购资格 |
| 旧机估值入口 | 怎么拿到抽签码？ | 估值一次，即得抽签码 |
| 抽签码展示 | 我的资格是什么状态？ | 码在此、今日是否已抽、是否中签 |
| 配额进度条 | 现在还来得及吗？ | 已发放配额实时可见，制造合理紧迫感 |

## 二、页面整体布局

```
┌─────────────────────────────┐
│ ① Hero 首屏                  │  产品主视觉 + 一句主张 + 智能主按钮
├─────────────────────────────┤
│ ② 会员开通引导               │  PLUS 权益 × 抢购资格绑定说明 + 开卡 CTA
├─────────────────────────────┤
│ ③ 旧机估值入口               │  "估值即得抽签码" + 单一入口按钮
├─────────────────────────────┤
│ ④ 抽签码展示                 │  我的抽签码 / 今日抽签状态 / 中签结果
├─────────────────────────────┤
│ ⑤ 配额进度条 + 预约抢购区     │  已发放配额进度条 + 中签后预约/抢购入口
├─────────────────────────────┤
│ ⑥ 活动规则脚注               │  规则摘要 + 完整规则入口
└─────────────────────────────┘
```

**Hero 首屏分流逻辑**（对应共识 §2 拉新目标的关键设计）：

- 未开通 PLUS：主按钮 =「开通 PLUS 抢早鸟资格」，点击直达 ②
- 已开通 PLUS：主按钮 =「估值抽签码」，点击直达 ③；② 模块自动折叠为权益确认条
- 分流依据会员状态前置判断，同一页面服务两类用户，不拆分落地页

## 三、模块详细设计

### 模块 ② 会员开通引导

**定位**：把"开卡"从花钱动作重述为"解锁资格"动作。

**内容构成**：
- 主文案强调资格绑定：「抢购资格与 PLUS 会员绑定，开卡即入抽签池」（引用共识 §2：抢购资格与 PLUS 会员绑定）
- 权益对比条：开卡所得 = 早鸟抢购资格 + PLUS 日常权益，前者为限时稀缺、后者为长期持有
- CTA：「立即开通 PLUS」

**设计方法论依据**：
- **福格行为模型（B=MAP）**：转化低是因为动机（M）不足。本模块不复述权益清单，而是把活动资格作为最强动机钩子前置；能力（A）侧保持一键开通、提示（P）侧 CTA 唯一明确，三要素同时补齐
- **损失规避**：文案框架采用"每天不抽签 = 浪费一次已到手的中签机会"，比"快来开卡"的收益框架更能驱动行动

**边界说明**：不承诺中签率，不出现"必中""保供"字样（中签率动态调整，见共识 §1，页面不得与机制冲突）。

### 模块 ③ 旧机估值入口

**定位**：把"以旧换新"从可选项重述为获取抽签码的必经且划算路径。

**内容构成**：
- 因果一句话：「旧机估个价，抽签码马上到」
- 辅助信息：估值免费、旧机可抵扣（换新性价比）
- 单一入口按钮：「去估价，领抽签码」→ 跳转拍拍估值流程页

**设计方法论依据**：
- **希克定律（Hick's Law）**：选项越多决策越慢。本模块只保留一个入口动作，用户无需在"估不估、怎么估"上消耗决策力
- **渐进式披露**：估值流程的细节（机型选择、成色判定等）全部收进拍拍流程页内，落地页只呈现入口与因果，符合共识 §3 拍拍约束——只做入口引导，不改动估值流程本身

**边界说明**：入口跳转后即离开本页进入拍拍估值页，本页不新增任何估值环节的 UI；用户完成估值返回后，④ 模块承接展示新获得的抽签码。

### 模块 ④ 抽签码展示

**定位**：用户资格的"状态中心"，消除"我到底有没有资格"的不确定感。

**内容构成**：
- 抽签码卡片区：醒目展示用户抽签码（大字号、等宽字体，接近"票据"的视觉隐喻，呼应"早鸟票"主题）
- 今日抽签状态：待抽 / 已参与 / 未中签（明日再来）三种状态文案
- 中签结果：中签后此卡片升级为中签凭证样式，引导进入 ⑤ 预约抢购

**设计方法论依据**：
- **状态可视性（Norman 反馈原则）**：系统必须让用户随时知道"发生了什么、现在处于什么状态"。抽签是异步、多日重复的行为，状态不透明会直接导致次日流失
- **峰终定律**：中签是整个活动的"峰"时刻，此卡片在中签态采用最强视觉反馈（票据盖章动效），把情绪高点落在产品页内，顺势导流预约

**边界说明**：「全程最多中签一次」「预约后不可更改、逾期作废」等规则原文展示于卡片下方小字（引用共识 §1 机制原文，不加工不简化），避免用户因误解规则产生客诉。

### 模块 ⑤ 配额进度条 + 预约抢购区

**定位**：用真实进度制造合理紧迫感，并承接中签用户的预约/抢购动作。

**内容构成**：
- 配额进度条：渲染"已发放配额"（数据源为 3C 苹果采销的动态配额，前台只做渲染，见共识 §1）
- 进度条旁文案：今日剩余抽签名额感知（由已发放配额换算，不虚构数字）
- 预约抢购区：未中签态收起；中签态展开——指定商品确认 → 预约锁定 → 抢购日提醒

**设计方法论依据**：
- **稀缺原理**：进度条将抽象的"名额有限"转为可视的具体刻度，稀缺感知直接驱动"今日就去估值抽签"的行动
- **目标梯度效应**：人对接近目标的进度更敏感。进度条同时服务两端——未中签者看到"名额在减少"，加速行动；中签者看到"只差最后一步预约"，完成闭环

**边界说明**：进度数据必须来自采销真实配额，严禁前端伪造或放大稀缺感（配额由采销基于整体库存动态控制，见共识 §1；页面质感与数据真实性共同构成"不 low"的底线）。预约后不可更改的提示在预约确认步强提醒一次。

### 模块 ⑥ 活动规则脚注

**内容构成**：抽签节奏、中签规则、预约规则摘要 + 「查看完整规则」链接。

**设计方法论依据**：**信任建立**——规则透明可回查是高客单价商品页的信任基础设施，间接支撑拉新转化。

## 四、视觉调性（对齐共识 §3 采销约束：质感向苹果官方看齐）

| 维度 | 规则 |
|---|---|
| 色彩 | 大面积黑白灰基底 + 单一强调色（苹果产品色），杜绝多色渐变堆砌与促销红黄撞色 |
| 字体 | 无衬线大字号标题，层级 ≤3 级；数据类信息（抽签码、日期）用等宽字体强化"票据感" |
| 排版 | 单屏单信息：一屏只回答一个问题，留白优先于信息密度 |
| 影像 | 产品图使用官方级渲染图/深色摄影背景，禁止抠图拼贴感素材 |
| 动效 | 克制：仅进度条生长、中签盖章两处轻动效，服务状态反馈而非装饰 |

## 五、与活动机制的一致性核对表

| 共识机制（§1/§2） | 方案对应设计 | 是否冲突 |
|---|---|---|
| 旧机估值 → 抽签码 → 每日抽签 → 预约 → 抢购 | 页面动线按机制链路排布（§一 1.2） | 无 |
| 每日抽签、最多中签一次 | ④ 模块每日状态 + 规则原文展示 | 无 |
| 预约后不可更改、逾期作废 | ⑤ 模块预约确认步强提醒 | 无 |
| 配额由采销动态控制，前台渲染已发放配额进度条 | ⑤ 模块进度条只渲染真实数据 | 无 |
| 抢购资格与 PLUS 绑定（拉新 10 万+） | Hero 分流 + ② 模块资格绑定叙事 | 无 |
| 换新占比 ≥15%（HVA 登门槛） | ③ 模块把估值重述为"必经且划算"路径 | 无 |
| 估值流程归拍拍（§3 约束） | ③ 模块仅入口引导，无流程改动 | 无 |
| 页面质感不 low（§3 采销约束） | §四 视觉调性专节 | 无 |

## 六、验收标准对照（对应任务验收标准）

| 任务验收标准 | 本方案落点 |
|---|---|
| 四个核心模块齐全 | 模块 ②③④⑤ 分别对应会员开通引导 / 旧机估值入口 / 抽签码展示 / 配额进度条 |
| 每个模块注明设计方法论依据 | §三 各模块"设计方法论依据"小节 |
| 引用活动机制、不冲突 | §五 一致性核对表逐条核对 |
| 质感符合苹果调性 | §四 视觉调性专节 |
| 只做展示层设计，不涉系统设计 | 全文无抽签机制、库存锁定的系统设计内容 |
